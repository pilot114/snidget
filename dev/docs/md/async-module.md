Модуль Async запускает приложение как долгоживущий HTTP сервер на PHP, без nginx и php-fpm.
Запросы обрабатываются по очереди в одном процессе, а ожидание сети не блокирует остальных клиентов:
каждое соединение живет в своем файбере.

### Запуск

    make async

Сервер откроется на http://localhost:8100, остановка - Ctrl+C. Под капотом это тот же php-контейнер,
что и для `make dev`, запущенный с переменной окружения `ASYNC=1`: _public/index.php_ видит ее
и создает `AsyncKernel` вместо обычного `Kernel`.

Раз в секунду сервер печатает в консоль статистику цикла событий: длительность итерации и сколько
времени заняли файберы (класс `Debug`).

### Как устроен

    AsyncKernel → Scheduler (файберы + цикл событий) → Server → Kernel::handle()

- `AsyncKernel` один раз загружает роуты и посредников и передает серверу обработчик запроса
- `Scheduler` крутит очередь файберов. Файбер, которому нужно дождаться сокета, приостанавливается
(`Scheduler::suspend(Wait::READ, $socket)`), а планировщик будит его, когда сокет готов
- `Server` принимает соединения, читает запрос целиком (с учетом `Content-Length`), отдает его ядру
и пишет ответ. Файлы из _public_ он отдает сам, а _.php_ файлы оттуда запускает отдельным процессом

Ядро то же самое, что и под php-fpm, поэтому контроллеры, посредники и события работают без изменений.

### Ограничения

- Один процесс обслуживает все запросы, поэтому объекты в контейнере - общие для всех клиентов.
Не храните данные запроса в свойствах сервисов: следующий клиент их увидит. Текущий `Request`
и `Logger` контейнер подменяет на каждый запрос сам
- Событие START случается один раз при старте сервера, FINISH - при остановке
- `dump()` печатает в консоль сервера, а не в ответ
- Одно соединение - один запрос (`Connection: close`), keep-alive не поддерживается
- Ошибка в одном запросе не роняет сервер: клиент получит 500, а трейс уйдет в лог

Модуль - учебный: он показывает, как устроена кооперативная многозадачность на файберах,
и не предназначен для production.
